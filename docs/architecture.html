03 — Decisions

Key Architecture Decisions

01
Server-side LLM only security
Client never talks to OpenAI directly. All LLM interaction happens on the server, keeping API keys secure and controlling cost.
02
Three-layer state architecture
Chat state lives in the database, app state lives in the iframe, and a contextual bridge links them through compact summaries.
03
Sandboxed iframes isolation
Third-party apps run in iframes with allow-scripts allow-forms only. No allow-same-origin. Communication via JSON-RPC 2.0 over postMessage with origin validation.
04
Namespaced tool router extensibility
Tools are namespaced as {appSlug}__{toolName}. The router owns the full invocation lifecycle: IDLE → TOOL_REQUESTED → APP_RENDERED → ACTIVE → COMPLETED.
05
Single active app simplicity
One app session at a time per conversation. Starting a new app terminates the previous session. No concurrent app complexity.
06
Intent tracking context
Each conversation has one active intent — either general_chat or app_intent. Determines which tool schemas are injected into LLM context.
07
Circuit breaker resilience
3 consecutive tool failures opens the breaker. Half-open after 30 seconds. Prevents cascading failures from misbehaving apps.
08
Context window management efficiency
Completed app interactions are replaced with context_summary, not raw JSON. Compaction triggers at 80% capacity. Last 10 messages always retained.

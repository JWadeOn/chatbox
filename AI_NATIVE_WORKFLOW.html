BRIDGE

RECONCILIATION.md

What does the fork already give us?

Maps spec assumptions to codebase reality. Classifies every feature as EXISTS, PARTIAL, NEW, or CONFLICTS. Discovers conventions (adopt / evolve / replace). Identifies pre-satisfied dependencies and ADR triggers. This is the brownfield branching point — CLAUDE.md and TASKS.md derive from here, not directly from the spec.

TASKS.md

What's next? What's parallel?

Dependency DAG where EXISTS features are pre-satisfied, PARTIAL features get modification tasks, and CONFLICTS get removal + replacement pairs.

docs/TASKS.md

Why does the pipeline branch? CLAUDE.md (context) and TASKS.md (execution) are independent outputs — neither requires the other. Generate them in parallel. In brownfield, RECONCILIATION.md must come first because both outputs need ground-truth about the existing codebase.

ITERATION

Retrospective

What did we learn? What's next?

Evaluates outcomes against PRD success metrics. What worked, what didn't, what surprised you. Recommendations feed back into updated planning docs for the next cycle.

RETROSPECTIVE.md

↺

Retrospective findings feed back into the planning pipeline — updated presearch, revised PRD, new technical evaluation. The pipeline is a loop, not a line.
